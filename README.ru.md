# Open Behavior Protocol

[English](README.md) · [Спецификация](docs/spec.ru.md) · [Инструкции для моделей](docs/agent-guide.ru.md) · [API и CLI](docs/api.md)

Open Behavior Protocol (OBP) — структурированный формат для описания и проверки поведения продуктов и внутренних систем. Процессы, данные, предметные правила, примеры, свойства и связи с реализациями собраны в общей модели, с которой могут работать люди, визуальные редакторы и программные агенты.

## Зачем нужен OBP

Требования часто разбросаны по обсуждениям, документам, макетам, тестам и коду. Команды и среды независимо реализуют одно и то же поведение, а связь между решением и кодом трудно проверить.

При агентной разработке эта проблема становится заметнее: агенты быстро меняют множество файлов, но созданные ими код и тесты сами по себе не показывают, как продукт должен работать. OBP даёт явное машиночитаемое место для поведения, его происхождения, примеров и свойств. Агенты и люди могут работать с одной структурой и связывать её блоки с реализациями в разных средах.

OBP отделяет **важное для предметной области** от **способа реализации в среде**. Формула тарифа или заметный пользователю сбой относятся к поведению, если они важны продукту. HTTP-маршруты, устройство хранения и выбор фреймворка относятся к среде. Одно поведение можно связать с мобильным приложением, сайтом и сервером без копирования процесса. Поведение, выведенное из кода, описывает то, как код предположительно работает; это не обязательно утверждённое требование.

## Что входит

- Текстовый формат с модулями, сущностями, средами и связями с реализациями.
- Блоки действий, выбора, параллельных ветвей, повторений и переиспользуемых определений.
- Типизированные значения, выражения, точная дробная арифметика и рекурсивные структурированные данные.
- Примеры, проверка пространства состояний, доказательство некоторых свойств и сравнение формальных моделей.
- Эталонная реализация на TypeScript, CLI и необязательный Node-адаптер для проверки наблюдаемых примеров реализации.
- Примеры: [публикация статьи](examples/publish-article.obp), [стоимость консультации](examples/consulting-fee.obp), [рекурсивное дерево выражения](examples/expression-tree.obp).

Версия 0.1 — ранняя эталонная реализация, а не универсальный инструмент доказательства. Точная семантика и ограничения перечислены в [спецификации](docs/spec.ru.md) и [инструкциях для моделей](docs/agent-guide.ru.md).

## Начало работы

Потребуются Node.js версии 23.6 или новее и npm. Ядро работает без необязательного решателя Z3.

```sh
npm install
npm run build
node bin/obp.ts check examples/publish-article.obp --strict
node bin/obp.ts inspect examples/publish-article.obp
node bin/obp.ts verify examples/publish-article.obp
npm test
npm run typecheck
```

`check` проверяет синтаксис, типы и ссылки, но не истинность требований. `inspect` выдаёт структуру для редактора или агента. `verify` проверяет заявленные свойства с допущениями и в области, указанными в отчёте. Код 0 означает завершённую проверку без обнаруженного нарушения, 1 — нарушение или ошибку, 2 — неполный или неприменимый результат. Пустой список свойств не доказывает незаданные требования.

Визуальный редактор и текстовый документ могут отображать одну структуру; хранение, отрисовку, контроль доступа и разрешение внешних ссылок обеспечивает приложение-хост. `format` сохраняет модель, но не сохраняет комментарии и исходное форматирование.

## Библиотека

```ts
import { check, inspect, verify, format, toModel, fromModel } from 'open-behavior-protocol';

const checked = check(source, { filename: 'publish-article.obp' });
if (!checked.ok || !checked.document) throw new Error('Invalid OBP document');

const diagram = inspect(checked.document);
const report = verify(checked.document, 'publish_article');
const model = toModel(checked.document, 'publish_article');
const text = format(fromModel('publish_article', model));
```

Node-адаптер и необязательное доказательство дробных свойств доступны через `open-behavior-protocol/node`. Подробнее — в [описании API и CLI](docs/api.md).

## Границы доверия

Структурно корректная модель может описывать неверное требование. Доказательство относится только к указанным свойствам, области и допущениям; `unknown`, исчерпание ресурсов и неразрешённые ссылки не являются доказательством. Сравнение формальных моделей не доказывает соответствие работающего кода. Адаптер запускает выбранную вызывающей стороной программу и проверяет только полученные наблюдения выбранных примеров.
